# 향후 사용자 ID별 격리 TODO

현재 운영자는 한 명입니다. 현재 공용 API 키나 관리자 키는 사람별 ID가 아니며, 이 문서는 사용자별 격리가 이미 구현되었다는 뜻이 아닙니다. 모델과 GPU는 실제 장치 하나를 공유하므로, 나중에 데이터를 사용자별로 나누더라도 모델 전환의 영향과 GPU 잠금은 전체 사용자에게 적용됩니다.

여러 사용자를 활성화하기 전에 다음을 설계하고 구현합니다.

- [ ] 사용자 ID를 검증하는 로그인과 서버 측 세션을 도입하고, 키 하나를 여러 사람의 신원으로 취급하지 않습니다. 자격 증명 발급·교체·폐기와 세션 만료도 처리합니다.
- [ ] 관리자와 일반 사용자 권한을 분리하고 서버에서 모든 모델 전환 요청의 권한을 검사합니다. 다른 사용자의 대화가 진행 중일 때 전환을 어떻게 알릴지와 관리자가 누구인지 결정합니다.
- [ ] 대화, 메시지, 이미지 작업·결과물, 작업 이벤트와 전환 요청의 소유자 또는 접근 범위를 저장합니다. 목록, 상세, 파일 다운로드, 이벤트 스트림, 검색, 재시도·취소에서 서버가 소유권을 확인합니다.
- [ ] 기존 단일 사용자 데이터를 명시적으로 소유자에게 귀속하는 마이그레이션과 롤백을 준비하고, 기존 데이터가 다른 사용자에게 보이지 않는지 확인합니다.
- [ ] 요청 중복 방지 키와 진행 조회의 범위를 사용자 또는 권한 있는 클라이언트별로 정의하여 다른 사용자의 요청 결과를 읽거나 충돌시키지 못하게 합니다.
- [ ] 전환과 복구의 감사 기록에 수행자 ID, 시간, 결과를 남기되 대화 내용, 비밀값과 인증 토큰은 기록하지 않습니다. 보관 기간과 접근 권한을 정합니다.
- [ ] 사용자별 할당량, 요청 제한, 긴 작업의 공정성과 대기 순서를 정합니다. 관리자 전환과 다른 사용자의 LLM·이미지 작업이 동시에 일어나는 상황을 검증합니다.
- [ ] 사용자 A가 사용자 B의 데이터·이벤트·파일·작업 결과에 접근할 수 없는지, 권한이 없는 사용자가 모델을 바꾸지 못하는지 통합 테스트합니다. 추측 가능한 ID나 URL을 아는 것만으로 접근을 허용하지 않습니다.

공유 GPU 잠금, gate 일시정지 소유권, 장애 복구와 모델 전환 안전성은 이 TODO와 별개로 현재 단일 사용자 단계에서 먼저 완료해야 합니다.
