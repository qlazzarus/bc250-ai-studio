# 이미지 생성 모드 발전 계획

작성일: 2026-11-15 · 보완일: 2026-11-15 · 상태: 기본 사전 구성·컴파일러·이력 저장 구현, 나머지는 확장 제안 및 검증 계획. BC-250 프롬프트 품질 검증 완료를 뜻하지 않는다.

## 목표와 범위

현재 직접 프롬프트를 입력하는 이미지 생성에 캐릭터 프로필, 이미지 편집과 다음 두 가지 작업 흐름을 단계적으로 더한다.

1. **프롬프트 구성:** 사용자가 사전에서 원하는 요소를 선택하고 직접 편집한다. LLM은 선택 사항을 정리하거나 보완하는 선택적 도구다.
2. **포즈와 참조 이미지:** 3D 포즈를 편집하고, 포즈 조건과 참조 이미지를 이용해 이미지를 생성한다. 첫 지원 범위는 SD 1.5 계열이다.

두 흐름 모두 최종 프롬프트와 모델 설정을 사용자가 확인한 뒤 기존 이미지 작업 큐에 제출한다. 기존 직접 입력 흐름과 API 호환성을 유지한다. 기본 사전 구성의 현재 동작은 [구현 현황](PROMPT_COMPOSER_CURRENT.md)을 따른다. 아래 LLM·캐릭터·이미지 편집·포즈 확장과 추가 필드는 제안이다.

## 현재 기준

- 사전 1.2.0·컴파일러 1.3.0, 100개 항목, 검색·선택·초안 적용 및 구성 v1 이력 저장이 구현되어 있다. 초안은 읽기 전용이고 적용 후 최종 입력에서 편집한다. 추가 설명은 자동 번역하지 않으며 P5에서 원문 반영/별도 보관을 명시적으로 선택한다. [P5 구현과 P6–P8 후속 설계](PROMPT_COMPOSER_P5.md)를 따른다. 후속 흐름의 LLM 제안은 미구현이다.

- Studio에는 모델별 옵션, 영속 작업 큐, 시드 및 결과 메타데이터가 있다. Realistic Vision v6는 SD 1.5 계열이며 BC-250 Vulkan에서 512×512 단독 생성 기록이 있다. 보조 모델을 합친 검증은 아니다. 상세: [모델 레지스트리](MODELS.md).
- 현재 Studio는 일반 채팅 API를 노출하지 않는다. LLM Client가 인증된 백엔드와 admission gate를 담당하는 분리 방향을 따른다. 브라우저가 llama나 gate에 직접 접속하지 않는다. [LLM Client 인계](NEXT_PROJECT_LLM_CLIENT.md)
- 이미지 작업은 기존 GPU 락, LLM admission/drain, 작업 복구 규칙을 따른다. 사전 선택과 포즈 편집은 이미지 GPU 점유 없이 가능해야 한다.
- 기존 아키텍처에는 업로드 API가 없다. 포즈 조건 이미지와 참조 이미지 보관은 새로 설계해야 한다. [아키텍처](ARCHITECTURE.md)

## 프롬프트 구성: 사전 우선, LLM 보조

### 리뷰와 결정

사전에서 주제와 세부 요소를 고르는 방식은 좋은 출발점이다. LLM 응답을 기다리지 않고 원하는 요소를 빠뜨리지 않게 고를 수 있고, 같은 선택을 반복하거나 결과를 수정하기 쉽다. 동시에 사전만으로 모든 상황을 표현하기 어렵고 선택 항목이 충돌하거나 모델별로 다른 문법이 필요할 수 있다. 따라서 **검색·다중 선택과 자유 입력을 기본으로 하고, LLM은 명시적으로 요청할 때만 초안을 제안**한다.

사전은 고정된 정답이나 품질 보장이 아니다. 긴 태그 나열은 모델에 따라 효과가 약하거나 요소 간 우선순위가 불명확할 수 있다. 처음부터 거대한 사전을 만들기보다 자주 쓰는 항목을 작게 구성하고 실제 결과를 보며 확장한다.

### 사용자 흐름

1. 이미지 모델을 선택한다. 모델 호환성과 지원 옵션을 표시한다.
2. 인물/대상, 외형, 의상, 행동, 장소, 구도, 조명, 화풍 등에서 검색해 필요한 요소를 선택한다. 카테고리는 출발 예시이며 필수 입력이 아니다.
3. 자유 입력을 더하고 생성된 초안을 확인·직접 편집한다. 지원 모델에서만 negative prompt를 편집한다.
4. 원하면 **LLM으로 다듬기**를 눌러 선택 항목과 요청을 전달하고 제안을 받는다. 원본과 제안을 비교한 뒤 적용하거나 버린다. LLM 사용 없이도 진행할 수 있다.
5. 최종 설정을 확인해 기존 생성 작업을 제출한다.

선택 사항 변경이 사용자가 직접 수정한 문장을 조용히 덮어쓰지 않도록 한다. 예를 들어 구조화된 선택과 편집 가능한 초안을 분리하고, 선택 변경 시 재구성 버튼과 덮어쓰기 안내를 제공한다. LLM 응답이 실패·지연·불완전해도 기존 선택과 편집 내용은 유지한다.

### 사전 데이터 제안

| 항목 | 용도 |
| --- | --- |
| 안정적인 ID, 분류, 한국어 표시명, 검색 별칭 | 화면 표시 및 선택 이력 |
| 모델 계열별 표현 또는 미지원 표시 | SD 1.5의 태그형 표현과 자연어 중심 모델을 구분 |
| 선택 그룹 및 충돌 관계 | 예: 카메라 앵글처럼 상충하기 쉬운 요소 안내 |
| 버전, 출처 및 활성 여부 | 선택 재현과 사전 변경 관리 |

초기에는 운영자가 관리하는 버전 있는 정적 데이터로 시작한다. 사용자가 원하는 표현을 직접 입력할 수 있어야 하며, 개인 사전 편집·공유는 사용 패턴을 확인한 뒤 결정한다. 충돌 관계는 경고 중심으로 시작하고 예술적 선택을 일률적으로 차단하지 않는다. 지원하지 않는 모델 계열에 대해서는 표현을 추측해 적용하지 않고 자유 입력을 허용한다.

결과에는 사전 버전과 선택 ID, 구성된 초안, 최종 프롬프트를 연결한다. 선택 항목이 이후 변경·삭제되어도 **최종 제출 문자열과 당시 선택 표현의 스냅샷**으로 이력을 확인할 수 있어야 한다. 기존 작업 재시도는 당시 확정된 설정을 사용한다.

### LLM 연동 경계

- LLM에는 선택 항목, 사용자의 추가 요청, 대상 모델 계열 및 지원 옵션을 전달한다. 응답은 prompt와 선택적 negative prompt 같은 제한된 구조로 검증한다. 모델이 지원하지 않는 옵션은 적용하지 않는다.
- LLM은 선택한 요소를 임의로 삭제하거나 모순을 숨길 수 있으므로, 원본 선택과 제안의 차이를 사용자가 확인한다. 빈 응답, 잘린 응답, 형식 오류는 적용하지 않고 재시도 또는 수동 편집을 제공한다.
- LLM 호출은 인증된 서버 측 연동을 거쳐 gate를 사용한다. Studio와 LLM Client 중 API 소유자는 구현 전 결정하며, 기존 서비스의 내부 주소·자격 증명은 브라우저에 노출하지 않는다.
- LLM 요청이 끝난 뒤 사용자가 이미지 생성을 요청한다. GPU 전환은 기존 admission 및 락 규칙을 따른다. LLM 모델 ID와 제안 적용 여부를 기록하되 원문 및 참조 이미지의 보관 정책은 기존 접근 권한에 맞춘다.

## 포즈 + 참조 이미지 모드

### 구성과 첫 범위

```text
Three.js 관절·카메라 편집 → OpenPose 호환 2D 조건 이미지 → ControlNet
참조 이미지 → 이미지 인코더 + IP-Adapter ─────────────→ SD 1.5 생성
사용자가 확정한 prompt / negative prompt ────────────→ 기존 작업 큐
```

- 처음에는 1인 전신, 몸통과 팔다리, 포즈 저장·불러오기, 카메라 조정, 참조 이미지 1장으로 제한한다. 손·얼굴 세부 관절, 다인 장면, 애니메이션은 후속이다.
- 포즈를 화면 캡처하는 데 그치지 않고 선택한 OpenPose 모델이 기대하는 관절 순서, 좌우, 색상, 연결선, 배경 및 이미지 좌표를 맞춘다. 가려진 관절의 표현, 투영 및 프레이밍 규칙도 고정하고 시각적으로 확인한다.
- IP-Adapter는 참조 특징을 유도할 뿐 동일한 얼굴·의상·캐릭터를 보장하지 않는다. 포즈와 참조 강도를 조정할 수 있게 하되, 허용 범위와 기본값은 실제 엔진과 품질 검증 후 정한다.
- SD 1.5는 1차 지원 범위이지 다른 계열이 BC-250에서 불가능하다는 판정이 아니다. 모델과 보조 모델의 조합별 capability 및 검증 상태를 표시한다.

### 저장과 재현

포즈 프리셋에는 버전, 관절 구조와 각도/위치, 카메라·투영, 캔버스 비율을 저장한다. 작업 제출 시에는 편집 가능한 포즈 데이터와 실제 생성에 사용한 2D 조건 이미지를 확정된 스냅샷으로 보존한다. 참조 이미지와 포즈 이미지의 불변 식별자 또는 해시, SD 체크포인트·ControlNet·IP-Adapter·이미지 인코더의 식별자와 버전/해시, 강도, 해상도, 시드, 엔진 버전과 최종 프롬프트를 함께 기록한다.

재시도는 변경된 프리셋이나 최신 파일을 다시 해석하지 않고 원래 작업의 스냅샷을 사용한다. 필요한 입력이 삭제되었으면 조용히 다른 파일로 대체하지 말고 재시도 불가를 표시한다. 업로드는 인증된 API에서 크기·픽셀 수·형식을 제한하고 실제 이미지로 디코딩해 검사하며, 서버가 생성한 ID로 비공개 저장한다. 클라이언트 파일 경로나 임의 CLI 인자는 받지 않는다. 참조 자산의 삭제와 연결된 작업의 재시도 가능 여부를 UI에서 설명한다.

### 선행 실기 검증: 구현 전에 수행

상류 [stable-diffusion.cpp](https://github.com/leejet/stable-diffusion.cpp/blob/master/README.md)는 SD 1.5 ControlNet과 IP-Adapter 지원을 명시한다. 이것은 저장소에 기록된 특정 설치 바이너리나 Vulkan 동시 실행의 증거가 아니다. 설치 바이너리의 버전·해시·도움말과 실제 지원 조합을 먼저 확인하고, 필요한 경우 엔진 변경의 영향과 롤백을 별도로 평가한다.

같은 SD 1.5 모델, 해상도, 시드, 프롬프트에서 다음을 차례로 비교한다.

1. 기준 SD 1.5 생성.
2. OpenPose 조건 + ControlNet.
3. 참조 이미지 + IP-Adapter 및 해당 이미지 인코더.
4. ControlNet과 IP-Adapter 동시 적용.

각 단계에서 모델 파일과 해시, CLI 인자, 장치·엔진 버전, LLM 정지 상태, 해상도·steps·seed, 성공/실패와 오류, 총 시간, 관찰 가능한 최대 메모리 및 결과 이미지를 기록한다. 512×512부터 시작하고, 반복 실행과 적어도 다른 포즈·참조 이미지에도 적용한다. 공유 메모리와 OS·서비스 여유분을 고려하며, 단일 성공을 안정성 인증으로 취급하지 않는다. 기존 운영 환경과 GPU 점유 절차에 따라 실기 시험을 진행한다.

품질은 포즈 조건 및 참조 이미지를 나란히 놓고 관절 위치·방향, 얼굴/헤어·의상 유사성, 아티팩트를 평가한다. 결과가 부족하면 강도와 입력 조건을 조정해 재시험하고 한계를 명시한다. 기능 공개 기준은 합의된 테스트 케이스에서 동시 실행 성공, 반복 시 자원·복구 안정성, 사용자가 받아들일 만한 포즈/참조 반영이다. 정량 기준은 예시 결과를 본 뒤 정하며 사전에 임의 수치를 성공으로 선언하지 않는다.

## 기능별 사용자 시나리오

| 시나리오 | 사용자의 흐름과 결과 |
| --- | --- |
| 캐릭터 재사용 | 캐릭터를 선택하고 지속 특징과 참조 이미지를 확인한다. 이번 장면의 의상·표정·행동을 별도 지정하고 생성한다. 이후 프로필을 바꾸어도 기존 작업은 당시 스냅샷을 가리킨다. |
| 사전 + 컴파일러 | 한국어로 사전을 선택하고 자유 입력을 추가한다. 모델별 초안과 미변환 항목을 확인하고 수정·확정한다. LLM 제안은 선택 사항이다. |
| 포즈 | 저장한 1인 포즈를 불러와 관절과 카메라를 조정하고, 출력 조건 이미지와 참조 이미지를 확인해 생성한다. 검증된 조합에 한한다. |
| 변형 | 기존 결과를 img2img 초기 이미지로 지정하고 변경 강도를 정해 새 파생 결과를 만든다. 캐릭터 참조는 별도로 선택한다. |
| 부분 수정 | 이미지 위에 수정 영역 마스크를 칠하고 프롬프트를 확인해 새 파생 결과를 만든다. 지원 모델과 검증된 전처리에서만 사용한다. |
| A/B 비교와 장면 이어가기 | 두 결과를 나란히 비교하고 하나를 새 작업의 부모 이미지로 명시한다. 프롬프트·설정을 수정해 다음 장면을 생성한다. 동일 인물이나 장면 연속성의 자동 보장은 없다. |

이미지 편집·포즈·프로필은 제안이다. 기본 사전 구성은 구현되어 있으며 이후 확장은 별도 계획이다. A/B 비교는 원본/파생 관계와 무관하게 기존 두 결과를 선택할 수 있으며 표시되는 모델·시드·설정 차이를 확인한다. 각 생성은 명시적 사용자 요청으로 기존 큐에 제출한다.

## Character Profile과 Scene Specification 초안

다음은 설계 초안이지 현재 API나 DB 스키마가 아니다. Character는 개별 작업과 독립된 안정 ID를 가지며 저장할 때마다 불변 revision을 만든다. 이미지 원본은 인증된 비공개 자산으로 저장하고 원본 바이트 SHA-256과 적용된 전처리 결과의 해시를 구분한다.

```json
{
  "character_id": "char_123", "revision": 3, "display_name": "예시",
  "identity_type": "fictional", "adult_status": "adult",
  "persistent_traits": {"face": "...", "hair": "...", "other": []},
  "reference_images": [{"asset_id": "ref_1", "sha256": "...", "role": "identity"}],
  "prompt_profile": {"dictionary_ids": ["hair.short"], "free_text_ko": "..."},
  "model_overrides": {"sd15": {"dictionary_ids": [], "approved_settings": {}}},
  "created_at": "...", "updated_at": "..."
}
```

```json
{
  "schema_version": 1, "character_revision_ref": {"id": "char_123", "revision": 3},
  "stable_traits_snapshot": {"hair": "..."},
  "scene_state": {"clothing": [], "expression": [], "action": [], "location": []},
  "composition": {"camera": [], "lighting": []},
  "selected_items": [{"id": "hair.short", "dictionary_version": "1", "value_snapshot": "short hair"}],
  "free_text": {"language": "ko", "original": "..."},
  "inputs": {"character_reference": {"asset_id": "ref_1", "sha256": "..."},
             "init_image": null, "mask": null, "pose_condition": null},
  "target": {"model_id": "realistic-vision-v6", "family": "sd15"}
}
```

장면의 의상·표정·행동은 기본적으로 프로필의 지속 특성을 변경하지 않는다. 모델별 설정은 registry에서 허용한 값만 적용하며 장면에서 수정 가능하다. 우선순위는 **명시적 장면 설정 → 캐릭터 모델별 기본값 → 모델 기본값**이다. 지속 특징을 장면에서 덮어쓰면 사용자에게 차이를 보여주고 그 작업에만 적용한다. 설정과 속성의 출처를 기록한다.

제출 시 프로필 revision 번호뿐 아니라 실제 사용한 지속 특징·모델 설정·참조 이미지 ID/해시와 Scene Specification, 컴파일 결과 및 사용자 최종 수정본을 작업에 불변 스냅샷으로 저장한다. 참조 파일과 모델 파일의 해시를 재시도 전에 대조하며 없거나 다르면 명확히 실패한다. revision 변경은 과거 작업을 바꾸지 않는다. 자산 삭제는 연결 작업의 재시도 불가를 안내하고 원본 삭제와 보유 정책을 적용한다. 동일 입력·엔진·환경에서도 GPU 비결정성으로 픽셀 단위 동일 결과는 보장하지 않으며, 저장 스냅샷은 동일 조건의 재실행을 위한 것이다.

### 인물 및 콘텐츠 정책

- 미성년자 또는 미성년자로 묘사되는 인물의 성적 묘사는 금지한다. 나이가 불명확한 성적 장면은 성인 여부가 충분히 확인될 때까지 진행하지 않는다. 나이 라벨이나 사용자 선언만으로 외형의 모호함을 해소했다고 간주하지 않는다.
- 실존 인물의 동의 없는 성적 합성은 금지한다. 실존 인물의 성적 표현은 각 당사자의 성인 여부와 해당 용도에 대한 유효한 동의를 확인할 수 없는 경우 차단한다. 참조 이미지·이름·프롬프트·출력 검토를 포함하며, 허위 선언이나 사진만으로 동의를 증명했다고 보지 않는다.
- 입력 및 최종 프롬프트 검토, 이미지 입력·출력의 위험 신호 검토, 불확실한 사례의 보류와 사용자 이의 제기/검토 경로를 설계한다. 프로필 수정, 자유 입력, LLM 제안, 기존 이미지 편집과 재시도에도 같은 정책을 적용한다. 자동 분류와 사용자 선언은 오탐·누락이 있으므로 완전한 판별을 주장하지 않는다.
- 동의 증빙을 다루게 되면 접근 제한·최소 수집·보관/철회/삭제 절차를 별도 확정한다. 정책 집행 수단이 준비되기 전 성적 실존 인물 합성은 지원하지 않는다.

## Prompt Compiler

```text
사전 선택 + 한국어 자유 입력 + Character revision + 장면 상태
 → Scene Specification 검증 → 모델별 표현 변환 → 초안과 미해결 항목
 → 선택적 LLM 제안 및 비교 → 사용자 직접 수정·확정 → 기존 job spec
```

- 한국어 UI와 원문 보존을 기본으로 한다. 사전 매핑은 모델 계열별 버전 있는 규칙으로 영어를 생성한다. SD 1.5 태그형과 Z-Image 등의 자연어형은 초기 전략이며 체크포인트별 품질 평가로 조정한다. 매핑되지 않은 한국어 자유 문장은 임의로 번역하지 않고 원문과 미변환 경고를 남긴다. 사용자가 영어를 직접 쓰거나 선택적으로 LLM에 번역을 요청한다.
- 항목별 안정 ID와 출처를 유지하고 누락·충돌·지원하지 않는 negative prompt를 검출한다. 길이·토큰 한계는 대상 모델/엔진 기준으로 점검하고 잘림 가능성을 명시한다. 컴파일러, 사전 및 템플릿 버전과 구성 요소, 초안 및 최종 문자열을 저장한다.
- LLM 제안은 먼저 구조화된 항목별 ID와 표현을 요구해 원본 ID의 누락·추가·중복을 기계적으로 비교한다. 원문 자유 텍스트의 의미 변경은 자동 판별이 불완전하므로 원문과 번역/제안 diff 및 불확실 항목을 보여주고 사용자가 승인한다. 정해진 항목 밖의 추가 내용은 명시적 사용자 승인 없이 적용하지 않는다. 검증 실패 시 초안을 보존하고 수동 수정으로 돌아간다. 의미 보존을 완전히 보장한다고 주장하지 않는다.
- 후보는 [Qwen3.6](https://github.com/AlibabaCloud-Official/Qwen3.6)과 [Gemma 4](https://ai.google.dev/gemma/docs/core)다. 모델별 크기·양자화, llama.cpp 및 Vulkan 호환성, 라이선스, 한국어→영어 의미 보존, 구조화 응답, 지연·메모리·거절 동작을 동일 평가셋에서 비교한다. 실제 운영 중인 LLM과 별개 후보이며 BC-250에서 실행 가능하거나 선택되었다는 뜻이 아니다. gate를 통한 서버 측 호출과 LLM 완료 후 이미지 GPU 전환 원칙을 유지한다.

## 모델 어댑터와 Capability Registry

기존 운영자 소유 모델 registry와 sd-cli 어댑터를 확장하는 작은 계약으로 시작한다. 공통 요청은 검증된 입력 ID와 선택된 기능 조합을 담고, 어댑터만 모델별 인자 및 전처리를 책임진다. 임의 경로·임의 CLI 인자는 허용하지 않는다. 다른 백엔드를 가정해 대규모 추상화하지 않으며 실제 두 번째 백엔드가 필요할 때 공통 경계를 재검토한다.

| 상태 | 의미와 노출 정책 |
| --- | --- |
| Verified | 해당 모델·보조 모델·엔진 빌드·Vulkan 장치·입력 및 설정 범위의 BC-250 실기 검증 증거가 있다. 검증 범위 밖으로 일반화하지 않는다. |
| Supported/Untested | 특정 엔진/모델 조합의 지원 근거가 있으나 해당 BC-250 조합의 실기 검증이 없다. 배포 기능으로 확정하지 않는다. |
| Experimental | 일부 구현·설정 또는 근거가 있으나 지원·품질·안정성 중 미해결 항목이 있다. 별도 실험 범위에서만 다룬다. |
| Unsupported | 해당 버전에서 미지원이 확인됐거나 제품 정책상 제공하지 않음. 이유를 남긴다. |

**미조사/Unknown은 네 상태 중 어느 것도 아니다.** 근거가 없을 때는 Unknown으로 두고 실행을 허용하지 않는다. Verified는 특정 정확한 조합에만 부여하며 모델 패밀리나 단일 기능의 성공으로 복합 기능을 추론하지 않는다. 증거에는 실행 명령, 해시, 설정 범위, 품질·반복 결과와 날짜를 연결한다. 파일 누락이나 버전 변경 시 실행 가능 여부를 다시 평가하며 과거 증거를 보존한다. 기존 `tested`/`configured` 및 옵션 `verified`와 새 상태는 다른 계약이다. 기존 값 자동 변환 없이 증거를 검토한다.

### Capability Matrix 초안

표는 **새 기능 계약에 대한 현재 평가**다. V는 기록된 제한 조합, E는 실험·운영자 기록, ?는 미조사다. `?`는 미지원이 아니다. 각 셀은 설치 엔진과 Studio API의 기능을 함께 단정하지 않는다. 범용 LoRA 선택과 특정 운영자 설정 LoRA도 다르다.

| 모델 | txt2img | img2img | Inpainting | ControlNet | IP-Adapter | LoRA |
| --- | --- | --- | --- | --- | --- | --- |
| SD 1.5 / Realistic Vision v6 | V: 512²/15 steps 기록 | ? | ? | ? | ? | ? |
| Z-Image NSFW v2 | E: 과거 768²/6 steps 기록, 현재 registry configured | ? | ? | ? | ? | ? |
| FLUX.2 Klein 4B Q4 | V: 512²/4 steps 기록 | ? | ? | ? | ? | ? |
| MOSS-Image NSFW Q4 | E: registry 운영자 제공 512²/20 steps + 고정 LoRA 0.7 기록, 새 검증 계약과 대조 필요 | ? | ? | ? | ? | E: 해당 운영자 설정 한정 |
| MOSS-Image Q8 | E: registry의 기본 모델 기록, 현재 LoRA 조합은 configured/미검증 | ? | ? | ? | ? | E: 현재 구성 검증 전 |

MOSS는 이미 registry에 Q4/Q8과 운영자 설정 LoRA가 있으며 임의 LoRA 일반 지원과 구별한다. Klein Q8은 별도 설정이며 Q4 실기 기록을 상속하지 않는다. [기존 모델 옵션](MODELS.md)과 `config/models.yaml` 사이의 날짜·상태 차이는 운영자 증거를 재확인한다. 위 V는 문서상 제한적 성공을 가리키며 새 계약의 반복·복구 기준 충족까지 뜻하지 않는다.

| 조합 | 현재 판단 |
| --- | --- |
| SD 1.5 txt2img + OpenPose ControlNet | Unknown: 설치 CLI·모델·Vulkan 실기 확인 필요 |
| SD 1.5 txt2img + IP-Adapter + CLIP Vision | Unknown: 설치 CLI와 파일 형식·실기 확인 필요 |
| SD 1.5 + ControlNet + IP-Adapter + CLIP Vision | Unknown: 각 단일 성공과 별도로 동시 실행 검증 필요 |
| img2img 또는 Inpainting + 캐릭터 참조/포즈/LoRA | 모델·엔진별 Unknown; 각 조합을 독립 평가 |

상류의 [이미지 전처리 문서](https://github.com/leejet/stable-diffusion.cpp/blob/master/docs/image_preprocessing.md)는 init, mask, control, IP-Adapter 이미지를 구분하지만 현재 설치 빌드의 기능이나 특정 모델과의 조합을 보장하지 않는다. 사용 가능한 조합, 해상도, 모델 해시, 전처리, 엔진 버전 및 자원 범위를 명시적으로 registry에 기록한다.

## 이미지 편집과 계보

img2img는 초기 이미지, 강도와 전처리(크롭·리사이즈)를 작업에 고정한다. Inpainting은 별도의 마스크, 좌표·해상도, 흰색/검정 의미, 보간, 경계 처리 및 적용 범위를 명시하고 미리보기와 동일한 입력을 실행한다. 각 기능은 설치 CLI와 정확한 체크포인트의 지원 및 BC-250 실행을 확인하기 전 구현 확정 범위에서 제외한다.

`character_reference`, `init_image`, `mask`, `pose_condition`은 서로 다른 역할의 자산 참조다. 같은 원본을 둘 이상으로 명시 선택할 수 있으나 암묵적으로 재사용하지 않는다. 파생 결과는 부모 asset ID, 관계 유형(`img2img`, `inpaint`, `continuation`), 입력 해시, 작업 ID와 불변 설정을 갖는다. 여러 부모가 가능하도록 관계 레코드를 두되 첫 구현은 주 초기 이미지 하나로 시작한다. 부모 삭제 시 자식과 이력은 유지하고 재현에 필요한 파일이 없음을 표시한다. A/B 비교는 이미지와 설정을 확인하는 UI 기능이며 생성 모델의 편집 지원을 뜻하지 않는다.

## 포즈 편집기 후보와 정합성

- [OpenPose3D](https://github.com/SiriuzNet/OpenPose3D)는 저장소에 MIT를 표기하며 Three.js 기반 3D 관절 편집, COCO-18/BODY_25, PNG 및 JSON 저장을 설명한다. 저장소는 SDXL 중심 설명과 SD 1.5 호환 주장도 제시하지만, 우리 대상 모델의 출력 정합성은 별도 검증해야 한다. 확인 시 공개 저장소의 릴리스·활동 및 유지보수 성숙도는 충분히 입증되지 않았다. 의존성·번들·모델 자산의 개별 라이선스와 보안 상태를 도입 전 확인하고 버전을 고정한다.
- [Three.js CCDIKSolver](https://threejs.org/docs/pages/CCDIKSolver.html)는 SkinnedMesh용 IK 애드온이다. 관절 제한, 목표점이 도달 불가능한 경우, 뒤집힘과 수동 회전의 조합을 시험해야 한다. 자체 경량 편집기 후보로 비교하며 IK 채택을 확정하지 않는다.
- 포즈 프리셋은 스켈레톤 버전·좌표계·관절 제한을 포함한다. 카메라 원근/직교, 종횡비, 캔버스와 출력 해상도, 좌우 미러링 시 신체 좌우 ID/색상, 가림·화면 밖 관절 처리를 고정한다. 정면·측면·후면·비대칭 포즈의 기준 이미지와 저장/복원 후 픽셀 및 관절 위치를 비교한다. 사용자가 보는 미리보기와 엔진에 전달한 이미지의 해시가 같아야 한다.
- 첫 범위는 1인 전신이며 손·얼굴 세부와 다인은 후속이다. 후보의 기능이나 라이선스 표기만으로 코드 재사용을 승인하지 않는다.

## BC-250 실기 체크리스트와 장애 복구

기존 GPU 락, LLM gate admission/drain, 직렬 큐, 전환 저널 및 장애 복구 규칙을 그대로 사용한다. 실험은 운영 환경의 기존 절차에 따라 수행한다.

- [ ] 실행 빌드·해시, 장치/드라이버, OS, 모델·ControlNet·IP-Adapter·CLIP Vision 파일/해시, 정밀도와 명령을 기록한다.
- [ ] 기준 유휴, LLM 실행, LLM drain/중지, 기본 모델, 기본+ControlNet, 기본+IP-Adapter+CLIP Vision, 기본+ControlNet+IP-Adapter+CLIP Vision 순으로 측정한다. CLIP Vision 등 개별 적재가 불가능한 엔진은 그 사실과 단계별 증분을 기록하고 개별 수치를 추정하지 않는다.
- [ ] 각 단계의 RAM(사용/가용), VRAM, GTT, swap 사용량·증감, 프로세스 및 시스템 최대 관찰 메모리, 생성·로드 시간, 성공/오류·오류 유형을 기록한다. UMA 공유 풀의 중복 집계를 주의하고 측정 도구·샘플 간격·누락 값은 `측정 불가`로 남긴다. 최대치는 관찰치이지 실제 절대 피크 보장이 아니다.
- [ ] LLM 요청 완료→drain→이미지 준비·생성→해제→LLM 복구/정상 응답까지 각 구간의 전환 시간과 실패를 기록한다. 활성 요청을 강제 종료하지 않는다.
- [ ] 동일 조건을 여러 번 실행하고 시도 횟수·실패 횟수·오류율을 기록한다. 해상도·조건 조합별로 별도 집계한다. OOM·타임아웃·취소·프로세스 중단 후 락 및 저널, 큐 상태, LLM 복구를 확인한다. 위험한 장애 주입은 격리된 환경에서만 수행한다.
- [ ] 관절 기준 포즈·참조 인물 유지와 아티팩트를 검토하고 결과 및 평가 기준을 남긴다. 검증된 해상도·입력 범위만 공개한다.

OOM 시 작업을 실패로 확정하고 오류 유형과 자원 진단을 남긴다. **자동 무한 재시도나 무단 해상도 변경은 금지**한다. GPU 프로세스 종료와 자원 해제, 저널·락 상태를 확인한 뒤 기존 복구 규칙에 따라 LLM을 복구한다. 상태가 불확실하거나 복구 실패면 GPU 작업을 차단하고 관리자 점검을 요구한다. 사용자가 입력·해상도를 바꾸어 새 작업을 제출할 수 있으며, 기존 retry는 원래 설정을 유지하고 반복 실패 가능성을 알린다. 재시도 횟수 제한과 진단 상세는 기존 계약에 영향을 주지 않도록 구현 시 명시한다.

## 단계별 우선순위·의존성·완료 조건

프롬프트 구성 우선의 세부 작업 분해와 UI 라이브러리 판단은 [프롬프트 구성 작업 계획](PROMPT_COMPOSER_EXECUTION_TASKS.md)을 따른다.

| 단계 | 의존성 및 완료 조건 |
| --- | --- |
| 0. 계약·정책 | 현 엔진·registry·보안 경계와 실기 증거를 확인한다. 캐릭터/장면/자산 스냅샷, 정책 집행과 미확인 상태를 확정한다. |
| 1. 사전 + Compiler MVP | 0 이후. 모든 모델의 한국어 사전 선택, 모델별 초안 또는 미지원 표시, 자유 입력, 미번역 표시, 편집·확정과 기존 큐 연동이 LLM 없이 동작한다. 모델별 품질 검증은 별도다. 사전 변경 후 기존 작업 재시도 및 기존 UI/API 회귀를 검증한다. |
| 2. Character Profile | 0과 1 이후. 지속/장면 상태 분리, 버전·참조 자산과 정책 집행을 제공한다. 수정·삭제 후 과거 스냅샷, 해시 검증과 재시도 실패 경로를 확인한다. |
| 3. 선택적 LLM | 1 및 인증된 LLM Client/gate 연동 이후. Qwen3.6/Gemma 4 후보를 평가하고 항목 비교, 사용자 승인, 실패 시 원본 보존 및 GPU 전환을 검증한다. 채택 모델이 없어도 단계 1·2는 사용 가능하다. |
| 4. 이미지 편집 실험 → MVP | 0·자산 입력/계보 이후. img2img와 inpainting을 각각 설치 엔진·BC-250에서 검증한 경우에만 해당 기능을 구현한다. 마스크 정합성, 원본 보존, 파생 이력과 재시도를 확인한다. A/B는 독립적으로 우선 구현 가능하다. |
| 5. 포즈 엔진 실험 | 0 이후, UI와 독립 진행 가능. 기본·각 보조 모델·동시 조합의 체크리스트와 실패 보고를 완성한다. 실패한 조합은 Verified로 표기하지 않는다. |
| 6. 포즈 MVP | 2·5 및 검증된 입력 자산 경계 이후. 1인 전신, 포즈 저장/복원, 조건 미리보기, 검증된 조합의 큐 연동과 스냅샷 재현을 확인한다. IP-Adapter 동시 조합이 실패하면 참조 없는 포즈만 별도 검증해 제공 여부를 결정한다. |
| 7. 모델·기능 확장 | 각 모델 및 조합을 따로 검증한 후 Z-Image, Klein, MOSS, 손·얼굴, 다인 등을 선택적으로 추가한다. 모든 이전 단계 완료가 필수는 아니다. |

각 단계는 해당 기능의 정책 집행, 인증/자산 접근 및 기존 큐·락·복구 회귀를 포함한다. Fake Engine 테스트는 API/UI 검증이지 실기 품질 증명이 아니다.

## 실패 시 대체 방안

| 실패 또는 제약 | 대안 |
| --- | --- |
| 사전에 번역 누락 또는 LLM 불가 | 한국어 원문을 보존하고 미변환 표시, 사용자 직접 영어 입력. 기존 직접 생성 유지. |
| LLM의 누락·추가 또는 형식 오류 | 제안 적용을 막고 구조화 초안과 원문을 유지; 재시도 또는 수동 편집. |
| IP-Adapter 미지원/메모리 부족 | 검증된 포즈 단독 또는 텍스트 캐릭터 프로필로 생성. 동일 인물 유지 보장 없음. |
| ControlNet 또는 동시 조합 실패 | 포즈 이미지를 미리보기/수동 참조로만 사용하거나 검증된 기능만 선택. 자동 대체 사용을 알린다. |
| img2img/Inpainting 미지원 | 기존 결과를 보존하고 프롬프트 재생성 또는 외부에서 편집한 이미지를 검증된 입력으로 사용. 업로드 기능 전에는 외부 결과를 자동 수용하지 않는다. |
| Three.js 후보 라이선스·유지보수 또는 IK 문제 | 라이선스가 확인된 경량 관절 편집/2D 조건 이미지 수동 작성으로 범위를 축소하고 정합성을 별도 검증한다. |
| OOM 또는 GPU 복구 불확실 | 작업 실패, 무한 재시도 중단, 기존 저널·락 복구 및 관리자 점검. 설정 변경은 명시적 새 작업으로 처리. |

## 결정이 필요한 사항

- 첫 사전의 실제 카테고리와 선호하는 표현: 태그 중심, 자연어 중심, 또는 모델 계열별 혼합.
- LLM 제안 API를 제공할 서비스와 사용 가능한 모델, 응답 지연 및 오류 처리 방식.
- 캐릭터 일관성의 목표: 분위기·의상 유사성인지, 얼굴까지 반복적으로 같은 인물이어야 하는지.
- 참조 이미지의 보관 기간과 삭제 시 기존 작업 재시도 정책.
- 실기 평가에 사용할 대표 포즈·참조 이미지와 품질 수용 기준.
