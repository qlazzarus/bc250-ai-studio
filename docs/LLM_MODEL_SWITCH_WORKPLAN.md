# LLM 모델 전환 작업 단계

현재 상태는 개발 중이며 운영 서버에 배포하지 않았습니다. 각 단계의 테스트와 호환성을 확인한 뒤 다음 단계로 진행합니다.

각 항목의 구체적인 미비 사항과 배포 차단 사유는 [배포 전 미비 사항](./LLM_MODEL_SWITCH_DEPLOYMENT_GAPS.md)을 참고합니다. 현재는 배포 준비 완료 상태가 아닙니다.

운영자 검토: 실제 환경 시험과 수동 배포를 계획하고, 기존 수동 전환의 안전 절차 우회는 예외로 허용합니다. 자동 전환은 기존 활성 모델 설정을 갱신하여 `ai-model status`에 반영하고, `ai-model list`와 동일한 설치 모델 목록을 사용해야 합니다. 자동 이미지·전환 경로의 공유 잠금과 gate 소유권 개선은 계속 필요합니다. 확정 내용과 남은 조치는 [운영자 회신 검토](./LLM_MODEL_SWITCH_DEPLOYMENT_GAPS.md#운영자-회신-검토)에 기록합니다.

최근 진행: 별도 관리 HTTP → Unix 소켓 → 단일 root 작업자 연결 후보와 기본 비활성화된 systemd unit을 추가했습니다. gate 전용 역할별 키·시작 hold, 이미지의 복구 보류 대기, root 전용 코드 준비 및 수동 배포 구성도 추가했습니다. 기존 읽기 전용 소켓 후보는 신규 작업자와 별개입니다. 운영 적용은 [수동 배포 초안](./LLM_MODEL_SWITCH_DEPLOYMENT_DRAFT.md)의 남은 실환경 검증 전까지 차단합니다.

추가 검증: Fedora 43 시험 VM에서 가짜 모델 전환과 gate 보류 이전·재시작을 확인했고, journal의 SELinux 레이블 불일치로 전환이 차단되는 문제를 재현·복구했습니다. 운영 `active-model.conf`에도 동일한 레이블 차이가 있어 운영 전환은 차단 상태입니다. 신규 상태 파일의 정책 레이블 설정과 전환 전 메타데이터 검사를 추가했으며, 이 후보는 Fedora 컨테이너에서 백엔드 256개 테스트와 Ruff가 통과했습니다. 변경된 후보의 systemd 통합 시험과 운영 파일 이전·롤백, GitHub Actions 배포 경로는 아직 미완료입니다.

운영 배포 판정: **아직 불가**입니다. 현재 `active-model.conf`는 systemd 작업자의 임시 파일과 SELinux 레이블이 다르고 운영 파일의 백업·레이블 이전·복원은 시험되지 않았습니다. 기존 Actions 배포는 Studio만 갱신하며 gate·공유 잠금·root 작업자를 함께 이전하지 않습니다. 새 후보 워크플로는 패키지만 생성하고 배포하지 않습니다. 수정된 후보의 실제 systemd 실패·복구, 게이트·Studio 동시 이전 및 GPU 경합을 시험한 뒤 최초 이전과 롤백, 이후 조율된 Actions 배포를 검증해야 합니다.

클라이언트 확인: 운영 LLM Client와 gate의 관리 키가 일치하지 않아 현재 `/control` 인증이 실패합니다. 시험 VM에서는 새 관리자 키를 클라이언트에 전달하고 프로세스 환경과 gate 역할을 확인했으며, `confirm-startup --expected-client-user`가 키 불일치 시 시작 보류를 유지하는 것도 검증했습니다. 운영 키는 아직 변경하지 않았습니다. 클라이언트는 이 키를 추론 요청에도 전송하므로 실제 llama 인증 호환성은 추가 확인해야 합니다.

범위 결정: 이번에는 모델 관리 API까지만 적용합니다. LLM Client 화면의 모델 선택·전환 기능은 이번 적용에 포함하지 않습니다. 기존 클라이언트의 gate 인증과 대화 호환성은 별도로 유지·검증해야 합니다.

로컬 검증: Python 3.12와 3.14 각각 백엔드 245개 테스트가 통과하고 root 네임스페이스 전용 6개는 일반 실행에서 제외됐습니다. 별도 Linux root 네임스페이스에서 이 6개를 실행해 실제 root 소유 파일의 잠금·권한과 비편집 코드 설치를 확인했습니다. Ruff와 프런트엔드 lint·빌드도 통과했습니다. 소켓 활성화 계약과 모의 프로세스의 단계별 강제 종료·재시작을 시험했지만 실제 systemd·SELinux·GPU는 사용하지 않았습니다. systemd unit은 운영 실행 파일 경로만 임시 복사본에서 대체하여 문법을 검사했습니다.

로컬 완료 항목과 서버에서 확인해야 할 항목 및 비밀값을 출력하지 않는 첫 확인 명령은 [남은 작업 구분](./LLM_MODEL_SWITCH_REMAINING_WORK.md)에 정리합니다.

1. **현황 조사와 사용자 결정 — 완료**: 운영 unit, 모델 설정, 권한과 기존 스크립트를 확인하고 단일 관리자·GPU 대기·중복 전환 거절·복구 실패 시 gate 유지 방침을 확정했습니다.
2. **이미지 작업 잠금 경합 — 구현, 통합 검증 진행 중**: 잠금 경합은 재시도하고 실제 생성 오류는 실패 처리합니다. gate의 진행 중 요청 수와 llama 슬롯을 확인합니다.
3. **gate 일시정지 소유권과 영구 보관 — 진행 중**: opt-in 소유권 모드는 관리자·Studio·전환 작업자 키를 분리하고 역할에 해당하는 hold만 해제하도록 제한합니다. gate 재시작 시 시작 hold를 남기고 root 확인 도구로 복구를 확인합니다. 구버전 호환 모드는 여전히 공유 키를 사용하므로 구버전 이전·저장 장애·실제 프로세스 재시작을 추가 검증해야 합니다.
4. **Studio 복구 연동 — 구현, 통합 검증 진행 중**: `STUDIO_ADMISSION_OWNED_HOLDS`를 명시적으로 켠 경우 작업별 ID를 gate 요청 전 복구 기록에 저장하고, 복구 후 자기 ID만 해제합니다. 기존 관리자 pause 유지와 중단된 작업의 health 실패·재복구를 단위 테스트했습니다. 실제 프로세스 강제 종료, 저장 실패, 배포 전환 및 기존 gate와의 통합 검증이 남았습니다. 기본값은 꺼져 있습니다.
5. **공유 GPU 잠금과 root 권한 경계 — 진행 중**: root 소유 사전 생성 잠금과 상태 기록, UID를 확인하는 소켓, 별도 root 소유 코드·가상환경 준비 스크립트와 systemd unit 후보를 추가했습니다. 전환은 기본적으로 꺼져 있으며 실제 root 소유 환경, SELinux 및 전체 경로 이전의 검증이 남았습니다. 수동 전환은 운영자가 안전 절차 우회를 허용한 예외입니다.
6. **모델 전환·복구 — 진행 중**: 전환 작업자는 공유 잠금과 gate hold·drain을 사용하고 기존 활성 설정을 바꾸어 health와 GGUF ID를 확인합니다. systemd 작업 결과 불명이나 복구 실패 시 hold와 journal을 유지합니다. 별도 모의 프로세스 강제 종료 후 복구 필요 상태와 hold 보존을 검증했으나 실제 systemd·GPU 경계 시험은 남았습니다.
7. **제한된 관리 API — 진행 중**: 전용 키를 사용하는 HTTP API와 UID를 확인하는 Unix 소켓, 단일 작업자를 연결했습니다. 목록·전환·조회·중복 방지·동시 전환 차단을 테스트합니다. root만 호출할 수 있는 복구 명령을 준비했으며 journal 불일치 등은 자동 복구하지 않습니다. 실제 서비스 설치, client의 인증·TLS 및 실환경 장애 검증이 남았습니다. 계약은 [모델 관리 API 후보](./LLM_MODEL_MANAGEMENT_API.md)에 기록합니다.
8. **통합 테스트와 배포 절차 — 미완료**: 경합·동시 요청·서비스 재시작·실패 및 복구를 시험하고, 한국어 배포·검증·롤백 명령을 준비합니다. 운영 서버에서 모델 전환이나 GPU 작업은 자동 실행하지 않습니다.

향후 다중 사용자 지원은 [사용자 ID별 격리 TODO](./USER_ISOLATION_TODO.md)에 따로 기록합니다. 현재 공용 인증을 사용자별 격리로 간주하지 않습니다.

최근 확인: 운영 gate에서 조회한 현재 `gemma4-e4b-hauhaucs` GGUF ID는 해당 모델 설정의 `MODEL_PATH`와 일치합니다. 다른 모델에는 아직 이 결과를 일반화하지 않습니다. gate 앱과 잠금·전환 후보를 결합한 테스트에서 이미지 잠금 대기, 진행 중 채팅 drain, 새 모델 재시작 실패와 이전 모델 복구 실패를 검증했습니다. systemd와 LLM 응답은 모의 처리했으며 root 서비스는 운영에 설치하지 않았습니다.

추가 진행: 운영자가 설치 모델 4개의 설정 문법과 GGUF 파일 존재를 확인했습니다. 전환 journal이 누락·손상되거나 접근할 수 없으면 이미지 작업을 안전하게 실패시키고 점검 안내를 작업 오류에 표시합니다. 실제 Fedora 배포 환경에서의 확인은 여전히 필요합니다.
