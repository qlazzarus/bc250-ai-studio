# 프롬프트 구성 우선 작업 계획과 프런트엔드 UI 검토

현재 남은 작업과 회귀 수정 상태는 [후속 작업 추적](../2026-11-17/PROMPT_COMPOSER_FOLLOWUP.md)에서 관리한다. capability 설정 누락 회귀(P5-R01)와 원래 129건 범위 재실행(P5-R02)은 통과했고, P5-C 브라우저 검증과 P6-UX 화면 검증도 로컬 Chromium에서 완료했다. 운영 배포·롤백과 GPU 품질 검증은 별도 미완료다.

작성일: 2026-11-15 · 갱신일: 2026-11-15 · 상태: P0~P4 코드 구현 완료(P3 수동 화면 검증 대기), 사전 1.2.0·컴파일러 1.3.0, P5-A/B 로컬 구현, P5-C 브라우저 검증 완료, P6-UX 화면 검증 완료. P6–P8은 후속 설계. BC-250 실기 프롬프트 품질 검증은 별도다. 상위 설계는 [이미지 생성 모드 발전 계획](../../../GENERATION_MODES_DESIGN.md)을 따른다.

## 현재 상황과 판단

프런트엔드는 React 19·TypeScript·Vite와 직접 작성한 CSS를 사용하며 UI 라이브러리 의존성은 없다. `App.tsx`가 생성 폼, 모델 선택, 작업 및 갤러리의 상태와 화면을 함께 다룬다. 일부 hooks와 컴포넌트는 분리되어 있지만 화면 전체가 분리된 것은 아니다. 현 생성 API는 최종 prompt 문자열과 모델 설정을 받는다. 사전 검색·다중 선택, 읽기 전용 초안과 편집 가능한 최종본, 모델 계열 전환과 경고는 이미 구현되어 있다. 상태 전이와 제출 전 검증을 다음 개선 대상으로 삼는다.

**권고: 지금 전체 디자인 프레임워크를 도입하거나 기존 화면을 전면 교체하지 않는다.** 프롬프트 구성 기능부터 컴포넌트 경계를 정하고 현재 CSS를 유지한다. 공통 색·간격·포커스 토큰과 버튼·입력·메시지 등은 실제 중복이 생기는 범위에서 정리한다. 검색·선택은 가능한 한 네이티브 입력과 체크박스부터 사용한다. 모달·팝오버처럼 직접 구현할 경우 포커스 관리가 복잡한 부분이 실제로 필요하면 [Radix Primitives](https://www.radix-ui.com/primitives/docs/overview/introduction)를 개별 도입하는 방안을 우선 평가한다. 프레임워크는 컴포넌트 분리나 상태 모델을 대신하지 않는다.

라이브러리 유무와 무관하게 키보드 조작, 라벨, 포커스 표시·복귀, 오류 안내, 작은 화면 및 스크린리더를 실제 화면에서 검증한다. 도입 재평가 계기는 검색 다중 선택·모달 등 복잡한 패턴이 여러 화면에 반복되거나 접근성/유지보수 비용이 눈에 띄게 커질 때다. 후보는 현재 React 버전·라이선스·유지보수·번들 및 빌드 영향, 현재 테마와 접근성 요구를 실제 컴포넌트 하나로 비교한다. 설치나 디자인 전면 교체는 별도 구현 작업이다.

## 우선순위와 범위

첫 완성 목표는 **모든 현재 모델에서 LLM 없이 한국어 사전 선택 → 대상 모델에 맞춘 초안 또는 미지원 표시 → 사용자의 수정·확정 → 기존 이미지 작업 제출 → 당시 구성 이력 확인**이다. 공통 구성기는 모든 모델에 적용하고, 모델별 변환 규칙과 품질 검증은 따로 관리한다. 매핑이 부족한 모델도 원문 및 직접 입력으로 사용할 수 있다. 직접 입력 모드는 유지한다. Character Profile, LLM 연동, 이미지 입력과 포즈는 이 목표를 막지 않는다. 현재 프롬프트와 설정의 재시도 동작, 모델별 negative prompt 제한, GPU 락·admission/drain·복구 계약은 유지한다.

의존성: `P0 → P1 → P2 → P3 → P4 → P5 → P6`. P0 결과는 [계약 조사와 결정](../../../PROMPT_COMPOSER_P0.md)에 기록했다. P5-A/B 로컬 구현 후 P5-C·릴리스 검증을 수행한다. 현재 P6(renderer·품질), P7(Scene v2), P8(LLM)은 설계 범위이며 구현은 별도 후속이다. 포즈·편집은 마지막 별도 트랙이다. 각 작업은 아래 완료 조건을 충족한 뒤 다음 작업으로 진행한다. P0–P4의 구성 API는 구현되어 있으며 [API 계약](../../../API.md)을 따른다. P5 이후 확장 내용은 후속 계획이다.

### P0 — 기존 계약 확인과 MVP 결정 · 완료

- **작업:** 기존 job 생성·retry·asset metadata의 저장 및 읽기 경로, 허용 필드와 구형 응답을 추적한다. 모든 모델의 계열 식별과 negative prompt capability를 확인한다. 실제 배포 버전·이주 정책도 확인한다.
- **완료 조건:** 입력/응답과 변경 대상 목록, 이전 job 및 asset의 호환성, 사전 이력 보존 위치를 결정하고 기록한다. Character/LLM/업로드 없이 완성할 범위가 명확하다.

### P1 — 사전 데이터 및 Scene Specification · 완료

- **작업:** 운영자 관리 정적 사전의 버전, 안정 ID, 한국어 이름·검색어, 카테고리, 모델 계열별 영문 표현·매핑 상태와 비활성 상태를 정의한다. Scene Specification v1에 선택 ID와 당시 값, 한국어 자유 입력, 대상 모델 계열을 담는다. 초기 카테고리는 인물/대상·행동·장소·구도·조명·화풍 등 소규모로 시작한다.
- **완료 조건:** 검색·다중 선택, 항목 변경/삭제 후에도 당시 표현 복원, 중복 ID 및 누락된 필수 표현 검증이 가능하다. 영어 미매핑 자유 문장은 변환한 것처럼 표시하지 않는다. 사전의 내용과 버전 출처를 문서화한다.

### P2 — 결정적 Prompt Compiler · 완료

- **작업:** Scene Specification과 모델별 사전을 순수 함수로 조합해 SD 1.5 태그형 또는 다른 모델 계열의 자연어형 초안, 미변환 한국어, 충돌 경고와 각 요소의 출처를 반환한다. compiler/사전 버전을 기록한다. unknown 모델은 SD 1.5 규칙으로 암묵 변환하지 않는다.
- **완료 조건:** 동일 입력·버전의 출력이 동일하며, 순서·중복·충돌·미매핑·빈 입력 및 모델 변경을 확인한다. 사용자의 자유 입력을 조용히 삭제·번역하지 않는다. 모델의 negative prompt 제약은 기존 API를 따른다.

P2 결과: `frontend/src/prompt/compiler.ts`는 스냅샷을 정해진 분류·ID 순서로 정렬하고, SD 1.5는 쉼표 구분 태그, Z-Image/FLUX/MOSS는 세미콜론 구분 영문 구절 초안을 제공한다. 자연어 표현은 아직 문법적으로 연결한 완성 문장이 아니다. 입력에 없는 의미를 만들지 않으며, 미매핑 항목과 한국어 자유 입력은 원문을 미해결 항목에 남긴다. 선택 ID·당시 사전 버전·표현을 결과에 함께 반환하고 중복과 상충 조합을 경고한다. 충돌은 차단하지 않는다. Fake·알 수 없는 계열에는 컴파일러 규칙이 없어 선택 표현을 미해결로 남기며 모델 기능 미지원 판정은 아니다. 컴파일러는 positive 초안만 다루므로 negative prompt는 기존 모델 capability 검증에 맡긴다.

모델 계열 변경 시 `changeSceneFamily`로 선택을 새 사전의 해당 계열 표현에 명시적으로 재결속한다. 사전에서 사라졌거나 비활성화된 항목은 기존 라벨을 보존하되 미해결 처리한다. UI가 `targetFamily`만 직접 수정하면 이전 표현이 남을 수 있으므로 P3는 이 함수를 사용하고 모델 변경 시 사용자 확인을 제공해야 한다. 기존 스냅샷에 계열 출처가 개별 저장되지 않는 P1 타입의 제약이며, 임의 데이터의 원래 계열을 역추적할 수 없다. P2 단위 검증 4건과 P1 단위 검증 4건, 프런트엔드 build/lint를 통과했다. UI/API 연결·문장 품질 및 실제 모델 검증은 아직 수행하지 않았다.

### P3 — 프런트엔드 구성기 · 구현 완료, 화면 검증 대기

- **작업:** 생성 폼에서 프롬프트 구성 영역을 분리해 사전 검색·선택, 한국어 자유 입력, 초안 생성과 편집 UI를 추가한다. 선택 상태, 생성 초안, 사용자가 수정한 최종본을 분리하고 재생성으로 편집 내용이 덮어써질 때 명확히 확인한다. 직접 입력으로 전환하거나 이전 내용을 보존할 수 있게 한다.
- **완료 조건:** 마우스·키보드로 검색/선택/해제/수정 가능하고 라벨·포커스·오류를 확인한다. 좁은 화면에서 사용 가능하며 모델 변경, 사전 변경, 뒤로 가기/취소 시 입력 손실이 없거나 사전에 명시된다. UI 전용 분리로 기존 갤러리·작업 큐 동작은 유지한다.

P3 구현: 사전 검색·분류·다중 선택, 한국어 원문, 초안 생성·미해결/충돌 표시 및 최종 프롬프트 적용을 연결했다. 구성값 변경 후에는 초안을 다시 만들도록 하고, 기존 최종 프롬프트를 덮어쓸 때 확인한다. 모델 계열 변경 시 선택을 재결속하고 최종 입력은 보존한다. Pixel Studio 전환 중 구성 상태는 메모리에 유지하며 페이지 이탈·새로고침 전 브라우저 경고를 요청한다. 구성 이력은 P4 전까지 저장되지 않는다. build/lint 및 기존 사전/컴파일러 단위 테스트 8건 통과. 브라우저 접근 호스트가 사용 불가여서 실제 클릭·키보드·작은 화면·스크린리더 및 기존 화면 회귀는 확인하지 못했다. 이 수동 검증이 끝나기 전 P3 완료 조건 전체는 미충족이다.

### P4 — 생성 요청 및 불변 이력 · 구현·관련 API 검증 완료

- **작업:** P0의 결정에 따라 선택 ID/표현 스냅샷, 원문, Scene Specification, compiler/사전 버전, 초안과 확정 문자열을 서버 측 작업 및 결과 메타데이터에 연결한다. 입력 크기·구조·허용 버전을 검증한다. 기존 `prompt`를 실행의 기준으로 삼는다. 결정된 optional `prompt_composition` 필드를 사용하며 기존 요청/응답을 호환되게 유지한다.
- **완료 조건:** 기존 클라이언트의 요청은 그대로 유효하고 구형 job/asset은 구성 정보 없음으로 읽힌다. 새 작업은 실제 제출 문자열과 당시 구성 정보를 조회할 수 있다. 사전·모델 기본값 변경 후 retry는 기존 확정 설정을 재사용한다. 구성 정보를 허위 실행 인자나 경로로 사용하지 않는다.

P4 결과: 선택적 `prompt_composition` v1을 `jobs.spec`에 저장하며, 항목별 사전 버전·표현, 한국어 원문, 생성 초안 및 미해결 항목을 포함한다. 서버가 스키마·크기·중복 ID·대상 계열을 검증하고 기존 최종 prompt를 실행 기준으로 사용한다. 작업·SSE·결과 metadata·sidecar·retry에 전파되며, 과거 데이터는 null로 읽는다. 프런트엔드는 capability 확인 후에만 전송하고 결과 상세에서 이력을 확인·재사용한다. 사전 표현은 이력이고 GPU 설정은 아니다.

관련 API 테스트 37건, 추가 크기·매핑 검증을 포함한 구성 이력 테스트 3건, 프런트엔드 build/lint 및 backend ruff가 통과했다. 전체 테스트를 시도했으나 macOS `chmod` 호환 및 Unix 소켓 권한 문제 등 모델 전환 관련 실패로 151건 통과·17건 실패 시 중단했다. P4와 무관한 환경 차이로 보이나 전체 회귀 통과를 주장하지 않는다. 브라우저 접근 불가로 P3/P4 실제 UI 검증은 미완료이며, 구 버전 서버 및 롤백 바이너리 실배포 검증은 P5에서 수행한다.

### P5 — 검증·정합성 개선 및 릴리스 준비

현재 세부 분할은 P5-A(입력 검증·적용 상태), P5-B(자유 입력·과거 복원), P5-C(브라우저 통합 검증)다. A/B 구현 완료와 P5 전체 검증 완료를 구별한다. [세부 계약·수동 절차](../../../PROMPT_COMPOSER_P5.md)를 따른다.


- **작업:** Fake Engine으로 직접 입력과 구성기 양쪽의 생성·큐·결과·재사용·retry를 검증한다. 모델 옵션, 데이터 이주/복구 및 오류 처리와 프런트엔드 빌드·lint를 확인한다. 접근성 수동 점검과 대표 한국어 사전 사용 시나리오를 기록한다.
- **완료 조건:** 기능 전환·모델 선택·직접 편집·재생성 경고·과거 이력·retry가 정상이며 기존 사용 흐름의 회귀가 없다. Fake 테스트 결과를 실제 GPU 품질 검증으로 표현하지 않는다. 배포 및 실기 시험은 기존 운영 절차에 따른 별도 단계다.

### 초기 P6 계획 이력 — 모델별 사용성 및 품질 검토

현재 P6는 아래 품질 검토와 모델별 renderer 설계를 함께 다룬다. 상세는 [P6 설계](../../../PROMPT_COMPOSER_P5.md#p6--모델별-렌더러-설계와-평가-구현하지-않음).

- **작업:** 대표 사전 선택과 사용자가 확정한 프롬프트로 각 사용 가능한 모델의 결과를 순차 비교한다. 변환 품질·유용한 사전 항목·사용성 문제를 기록한다. 이미 검증된 모델/설정 범위와 GPU 운영 절차를 지킨다.
- **완료 조건:** 사용자의 예시 평가와 실패 사례가 기록되고 사전 개선 목록이 정리된다. 실기 수행 전에는 미검증으로 표시한다. 실기가 불가능해도 P5의 기능 검증 결과와 구별해 보류할 수 있다.

### 초기 P7 계획 이력 — 모델별 컴파일 확장

아래 내용은 현재 P6 renderer 설계로 통합했다. 현재 P7은 [Scene v2·캐릭터 귀속 설계](../../../PROMPT_COMPOSER_P5.md)이며 이번에는 구현하지 않는다.

- **작업:** 모든 계열의 기본 구성을 제공한 뒤 Z-Image NSFW v2, FLUX.2 Klein 4B, MOSS-Image 등의 표현 범위와 모델별 품질을 각각 고도화한다. Capability Registry는 기존 모델별 옵션과 증거를 연결하되 특정 모델 성공을 다른 모델로 일반화하지 않는다.
- **완료 조건:** 각 모델별 표현 전략·검증 상태·미지원 처리와 예시가 있고, 검증 전 지원을 약속하지 않는다. 현재 모델 실행 기능과 새 컴파일러 지원 상태를 구분한다.

### P8 — 선택적 LLM 제안

- **작업:** 인증된 LLM Client/gate 연동 경계를 확정하고 Qwen3.6·Gemma 4 후보를 평가한다. 구조화 제안의 선택 항목 ID 누락·추가를 비교하고 자유 문장의 의미 차이를 사용자에게 보여준다.
- **완료 조건:** 사용자가 적용/거부할 수 있고 실패나 불완전 응답에서 원본이 보존된다. 사전만으로 생성하는 흐름은 계속 작동한다. LLM 요청 종료 후 기존 GPU admission/drain과 이미지 큐가 안전하게 이어진다.

## 고도화 1.2.0 — 사전 적용 범위와 컴파일러 안전장치

기존 1.1.0의 실사용 문제는 두 가지였다. 배포된 MOSS 모델 2종에서 88개 사전 항목이 표현 없이 `미변환`으로 남았고, 초안이 서버 한도나 모델의 텍스트 창을 넘어도 사용자가 알 수 없었다.

**사전 1.2.0.** `moss-image` 계열도 자연어형 표현을 쓰므로 Z-Image/FLUX와 같은 문구를 재사용했다. 이는 이미 큐레이션된 운영자 초안을 구조적으로 재사용한 것이며, BC-250 실기 품질·모델 지원 검증이 아니다. 현재 `sd15`·`z-image`·`flux2`·`moss-image` 모두 100/100 항목이 표현을 가지며, `fake`와 알 수 없는 계열은 계속 미제공이다. 기존 12개 ID·카테고리·표현과 1.0.0 스냅샷은 그대로다. `familyCoverage()`가 계열별 적용 가능 개수를 반환해 화면이 미리 알린다.

**컴파일러 1.2.0.** 동작 변경은 다음과 같다.

| 경고 코드 | 의미 | 초안 처리 |
| --- | --- | --- |
| `duplicate_phrase` | 서로 다른 ID가 같은 표현을 보존 | 중복 구절을 한 번만 출력 |
| `over_limit` | 초안 8,000자 또는 선택 100개 초과(서버 계약) | 자르지 않고 그대로 출력, 화면에서 경고 |
| `token_budget` | `sd15`에서 대략 77 토큰 초과 | 자르지 않고 경고만 |
| `conflict`·`duplicate`·`unsupported_family`·`empty` | 기존 의미 유지 | 변경 없음 |

토큰 수는 단어 수 기반 근사치이며 정확한 토크나이저 계산이 아니다. 자연어 계열에는 이 경고를 적용하지 않는다. 초안을 자르거나 의미를 만들어 넣지 않는 기존 원칙은 유지한다.

**UI.** 선택한 항목을 해제 가능한 칩으로 보여 주고, 선택 시점 계열에서 표현이 없는 항목은 경고색으로 표시한다. 사전 목록에서도 `이 모델은 미변환`을 미리 보여 주며, 카테고리 선택은 기존 `action`/`location`/`composition` ID를 유지한 채 화면 그룹(`pose`/`setting`/`camera`)으로 묶는다. 결과 이력에는 미변환 선택과 초안에서 빠진 `unresolved`를 함께 표시한다. `appliedForFamily()`로 다른 계열의 확정 스냅샷이 제출되지 않도록 방어한다.

**검증 상태.** 프런트엔드 단위 테스트 20건, `npm run build`, `npm run lint`, 백엔드 구성 스키마 5건이 통과했다. SSH 터널(`http://localhost:18080`)로 배포 서버를 점검했고, 결과는 아래 절에 기록한다. 브라우저 실제 클릭·키보드·좁은 화면 확인과 BC-250 프롬프트 품질 평가는 여전히 미완료다.

## 배포 서버 점검 기록 (2026-11-15, SSH 터널 18080)

`ssh -L 127.0.0.1:18080:127.0.0.1:80` 터널과 Caddy 정적 배포를 통해 확인했다. 이 점검은 배포본 인자·스키마 검증이며 GPU 추론 결과의 품질 평가가 아니다.

| 항목 | 결과 |
| --- | --- |
| 정적 UI | `GET /` 200, 이 저장소의 빌드 산출물 |
| API | `system/health`·`system/status`·`system/capabilities`·`models` 모두 200 |
| 엔진·정책 | `engine: sdcpp`, `simulated: false`, `policy: chat_priority`, `recovery_required: false` |
| 구성 지원 | `prompt_composition.schema_versions: [1]` 광고됨 |
| 모델 | 9개 등록, `fake`만 `unavailable`(실행 불가), 나머지 8개 `execution_enabled: true` |
| 거부 경로 | 계열 불일치·추가 필드·스키마 버전·중복 ID·매핑 불일치·길이 초과·미지원 모델/해상도/negative·잘못된 토큰이 모두 422/401로 거부 |
| 대용량 본문 | 당시 점검에서 32 KiB 초과 요청이 `BodyLimit`의 413으로 차단됨. 소스 기본 HTTP 한도는 64 KiB이며 구성 객체의 별도 32 KiB 한도와 구분 |
| 이력 | 최근 완료 작업·asset의 `prompt_composition`은 `null`(구 데이터) — 신규 제출분부터 저장 |

주의할 점은 배포본 JS가 로컬 `dist`와 완전히 같지 않다는 것이다. 배포본은 `sessionStorage` 토큰 fallback이 제거된 빌드이며, 현재 소스(`constants.ts`)에는 fallback이 남아 있다. 다음 배포 시 이 차이를 확인해야 한다. 키가 번들에 포함되는 방식 자체는 [frontend README](../../../../frontend/README.md)의 경고를 따른다.

같은 점검을 반복하려면 `scripts/probe_studio_prompt_composition.py`를 사용한다. 모든 작업 요청이 의도적으로 거부되는 페이로드이므로 큐나 GPU에 아무것도 들어가지 않는다.

```sh
STUDIO_API_KEY=<client key> STUDIO_BASE_URL=http://127.0.0.1:18080 \
```
