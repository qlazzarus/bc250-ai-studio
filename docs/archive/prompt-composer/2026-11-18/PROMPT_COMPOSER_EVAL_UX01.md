# EVAL-UX01 — 설명 작업의 효율·의도 보존 평가

작성일: 2026-11-18 · 상태: **실행 완료(규칙 모드 기준, 실제 LLM 미연결)** · 상위: [실행 태스크](../../../PROMPT_COMPOSER_EXECUTION_TASKS.md) · 현재 구현: [PROMPT_COMPOSER_CURRENT.md](../../../PROMPT_COMPOSER_CURRENT.md)

이 문서는 설명 → 초안 승인 경로를 **측정한 값**과 **측정하지 않은 값**을 구분해 기록한다. 숫자는 모두 `scripts/eval-ux01/`의 스크립트가 현재 코드로 다시 계산할 수 있다.

```sh
node --experimental-strip-types scripts/eval-ux01/evaluate.mjs        # 규칙 모델
node --experimental-strip-types scripts/eval-ux01/evaluate.mjs --json # 원자료
sh scripts/eval-ux01/browser.sh                                       # 실제 UI 클릭 측정
node --experimental-strip-types --test frontend/tests/prompt-eval-ux01.test.mjs
```

### 기대값을 어떻게 만들었나

`expected`(장면에 있어야 할 항목), `forbid`(있으면 원치 않는 추가), `unmatchedKo`(사전이 표현할 수 없는 구절)는 **문장을 읽고 직접 판정**했다. `suggestSelections`를 실행해 그 출력을 복사하지 않았다. 복사했다면 recall이 100%가 되고, 그 숫자는 아무것도 말해 주지 않는다. 이 규칙은 테스트로 고정했다(`the expectations were not derived from the engine under test`).

각 기대 항목에는 판정 이유(`why`)가 붙어 있고, fixture 파일은 제품 모듈을 import하지 않는다. 리뷰어가 "왜 이 항목이 기대인가"를 코드 실행 없이 확인할 수 있어야 하기 때문이다.

### 지표 정의

| 지표 | 정의 | 분모 |
| --- | --- | --- |
| recall | 기대 항목 중 규칙이 제안한 수 / 기대 항목 전체 | 38 |
| precision | (제안 − 원치 않은 추가) / 규칙이 제안한 전체 | 34 |
| precision(판정 가능) | 미분류를 제외하고 계산 | 32 |
| 원치 않은 추가 | `forbid`에 있는데 규칙이 제안한 수 | — |
| 미분류 | 기대에도 `forbid`에도 없는 제안. **사람이 판정해야 함** | — |
| 클릭 수 | `PROTOCOL`의 UI 절차로 계산. 초안은 자동 미리보기라 클릭 0 | — |

- 원치 않은 제안 3개는 **클릭을 쓰지 않는다.** 수락이 항목별이므로 사용자는 그냥 넘기면 된다. 대신 "알아채고 넘기는" 비용이 있고, 그 횟수를 `distractors`로 따로 기록한다.
- 초안 승인 클릭은 위 합계에 포함되지 않았다. 초안은 자동 미리보기이므로 승인 전 클릭은 0이다.

## 3. 실제 UI 측정 (브라우저)

규칙 모델의 클릭 수를 그대로 믿지 않고, 같은 12장면을 **실제 화면에서 클릭**해 확인했다. 세 번 연속 실행에서 결과가 같았다.

| 확인 | 결과 |
| --- | --- |
| 클릭 수 = 모델(수락+찾기) + 시작 선택 + 적용 | **일치 (12/12)** |
| 화면의 초안 문자열 = `compileScene` 출력 | **일치 (12/12)** |
| 최종 프롬프트 = 초안 (적용 후) | **일치 (승인 11/11)** |
| 적용 버튼이 없는 장면 | **0** |
| 초안이 비어 승인 불가 | **1 — landscape-lake-dusk** |
| 원치 않은 제안이 수락됨 | **0** |

총 클릭 **43회**(장면당 3.58). 모델의 80회와 다른 이유는 모델이 **누락 항목을 손으로 메우는 27클릭을 가정**하기 때문이다. 브라우저 측정은 자동화가 그 보정을 하지 않으므로, 실측값은 "제안을 그대로 받아들였을 때"의 비용이다. 두 숫자는 서로 다른 질문에 답한다:

- **80회** = 누락을 전부 손으로 고친다고 가정한, 의도 보존 최대 비용.
- **43회** = 제안만 받아들이고 누락은 방치했을 때의 실제 클릭 수(= 초안이 원문의 일부를 표현하지 못하는 상태).

자동화 소요 시간은 7.6초(12장면)였으나 **사람의 시간이 아니다.** UI 반응만 측정한 값이며, 입력→승인 소요 시간 지표로 쓸 수 없다.

**8번은 규칙 경로에만 해당한다.** 부분 변경 요청(`partial_change`)은 `partialScope`가 `카페`를 `out_of_scope`로 차단하는 것을 같은 fixture에서 확인했다(아래 5절). 즉 "규칙 제안 목록"과 "AI 부분 변경"은 범위를 다르게 다룬다.

## 5. 부분 변경 (LLM-I06 경로)

`partial-lighting-only` 한 장면으로만 측정했다. 나머지 11장면은 이 경로를 쓰지 않는다.

| 항목 | 값 |
| --- | --- |
| 요청 범위 | `lighting` 하나 |
| 잠긴 값 | 인물, 흰 셔츠 **2개** |
| 수락된 제안 | **어두운 조명 1개** |
| 범위 밖으로 차단 | **카페 1건** (`out_of_scope`) |

원문에 `카페`가 있어도 조명만 바꾸는 요청에서는 추가되지 않는다는 점을 실제 코드 경로로 확인했다.

## 6. 상황 후보 (VAR02 경로)

같은 12장면에 **스크립트로 작성한** 후보 3장을 넣어 배선을 측정했다. 후보 문장은 모델 출력이 아니며, 후보 품질·`target_groups` 준수는 이 결과로 판단할 수 없다.

| 항목 | 값 |
| --- | --- |
| 장면당 후보 | 3장 (스크립트) |
| 장면당 적용 가능 | 2장 |
| 차단 | 1장 — 의상 변경 시도(범위 밖), **12장면 모두 동일하게 차단** |
| 적용→되돌리기 | **12/12** 적용 전 장면이 그대로 복원됨 |
| 클릭 | 장면당 3회 (요청 1 + 적용 1, 찾기 1) — 총 **36회** |
| 자동 적용 | **0건.** 후보가 도착해도 선택은 바뀌지 않는다 |

## 7. 측정하지 않은 것

아래는 **값이 없다.** 추정치를 적지 않았다.

- **입력 → 초안 승인 소요 시간(사람).** 자동화 시간만 있고 사람은 없었다.
- **실제 LLM 응답의 정확도·지연·`target_groups` 준수.** 호출 0회. 후보와 제안 카드는 모두 스텁/스크립트다.
- **사용자 주관 평가.** 수락률·만족도·불편 지점은 사용자 없이 측정 불가.
- **실제 생성 이미지 품질.** QUALITY01/02의 몫이며 이 평가 범위가 아니다.
- **"최적" 판정.** 비교 대상이 없다. 규칙 모드 한 가지 조건의 측정일 뿐이다.
- **실제 확대(200%)·보조기기·소프트 키보드.** AT01/AT02.

또한 이 평가는 **제품 동작을 바꾸지 않았다.** 사전·컴파일러·Scene v1·API·저장 계약 모두 그대로다.

## 8. 재현과 회귀

| 명령 | 기대 |
| --- | --- |
| `node --experimental-strip-types scripts/eval-ux01/evaluate.mjs` | 12장면 표 + 합계 |
| `sh scripts/eval-ux01/browser.sh` | `checks 8, failed 0` (3회 연속 확인) |
| `node --experimental-strip-types --test frontend/tests/prompt-eval-ux01.test.mjs` | 10 tests pass |

`frontend/tests/prompt-eval-ux01.test.mjs`는 **분모와 인용된 합계를 고정**한다. 사전이나 매처를 바꾸면 이 테스트가 깨지고, 문서와 테스트를 함께 갱신해야 한다. 이것은 의도된 마찰이다: 조용히 다른 숫자가 되는 것보다 낫다.

마지막 테스트는 **커밋된 원자료(`results.json`)와 현재 코드의 실행 결과를 비교**한다. 문서가 인용한 숫자와 코드가 어긋나면 여기서 깨진다.

원자료는 `docs/evidence/prompt-composer-eval-ux01/`에 있다.

| 파일 | 내용 |
| --- | --- |
| `results.json` | 장면별 기대·제안·클릭·초안 (규칙 모델) |
| `summary.txt` | 같은 내용의 사람이 읽는 요약 |
| `browser.json` | 실제 UI 측정값 (장면별 클릭·초안·일치 여부) |
| `browser-results.json` | 브라우저 검사 8건의 PASS/FAIL |
