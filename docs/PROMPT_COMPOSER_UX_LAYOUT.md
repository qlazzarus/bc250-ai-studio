## 2. 데스크톱 배치안 (초안 — §4 실측으로 2열 부분 폐기)

> **주의**: 아래 2열 배치안은 U02 실측에서 기각됐다. 실제로는 §3의 1열 흐름을 데스크톱에도 쓴다. 결정 근거는 §4.

```
┌ shell ─────────────────────────────────────────────────────────────────────────────┐
│ header: Art Studio                                            [Pixel Studio]        │
│ statusbar: 정책 · 관리자 허가 안내                                                   │
├ .workspace (2열: 생성 .88fr | 작업 큐 1.12fr) ─────────────────────────────────────┤
│ ┌ panel.composer (생성 폼, onSubmit 유지) ──────────┐ ┌ panel.jobs ─────────────┐ │
│ │ 새 이미지 [모델 계열 배지]                       │ │ 작업 큐        [새로고침] │ │
│ │ ① 모델 [select]                                  │ │ JobCard…                 │ │
│ │ ② 사전 구성 [열기/닫기]                          │ │ Pagination               │ │
│ │ ┌ prompt-stage (열렸을 때 2열, 폭 충분할 때만) ┐ │ └──────────────────────────┘ │
│ │ │ 좌: 탐색 (explore)        │ 우: 장면/미리보기 │ │                              │
│ │ │  · 검색                   │  · 선택한 장면   │ │                              │
│ │ │  · 분류 칩(선택 n)        │  · 추가 설명     │ │                              │
│ │ │  · 항목 목록(스크롤)      │  · 미리보기      │ │                              │
│ │ │  · 0건 복구 안내          │  · 적용 버튼     │ │                              │
│ │ └───────────────────────────┴──────────────────┘ │                              │
│ │ ③ 최종 프롬프트 [textarea]  (위치 유지)          │                              │
│ │ ④ 해상도/수량 · Steps/CFG/Seed                   │                              │
│ │ ⑤ [이미지 생성]                                  │                              │
│ └──────────────────────────────────────────────────┘                              │
└────────────────────────────────────────────────────────────────────────────────────┘
```

- **좌(탐색)** = `사전 검색`, `분류 칩`, `항목 목록`, `0건 복구`. "고르는 곳"이다.
- **우(장면/미리보기)** = `선택한 장면 요약`, `추가 설명(원문)`, `제안(접힘)`, `미리보기`, `적용`. "확인하고 확정하는 곳"이다.
- 최종 프롬프트·파라미터·생성 버튼은 지금처럼 form 안, `prompt-stage` **아래**에 둔다. 흐름이 "고르기 → 확인 → 확정 → 생성"으로 한 방향이 된다.
- 2열은 **폭이 확보될 때만** 켠다. 좁으면 1열로 떨어뜨린다(§4). 실측 결과 현재 구성에서는 항상 1열이다.
- `.workspace` 열 비율은 **바꾸지 않는다.** 작업 큐·갤러리와 함께 흔들리고 U02 금지 범위에 걸린다.

## 4. 2열 전환 기준 — 실측으로 기각, 단일 열 확정

U02에서 실제 Chromium으로 측정한 결과 **2열 기본안을 철회**한다. U01 초안의 "960px 이상 2열"은 뷰포트 기준이었는데, 실제 컴포저 폭은 그보다 훨씬 좁다.

측정값 (Chromium 149, headless, 2026-11-16):

| 뷰포트 | 컴포저 폭 | `.workspace` 열 |
| --- | --- | --- |
| 1440px | 566px | 2열 |
| 1280px | 496px | 2열 |
| 1100px | 416px | 2열 |
| 960px | 355px | 2열 |
| 900px | 328px | 2열 |
| 820px | 638px | 1열 |
| 768px | 638px | 1열 |

- `.workspace`가 2열인 구간(820px 초과)에서 컴포저는 **328–566px**다. 작업 큐가 1.12fr를 차지하기 때문이다.
- 이 폭을 반으로 나누면 좌우 **165–283px**다. 항목 목록이 이미 230px 스크롤 영역을 쓰므로 2열은 목록을 더 좁힌다.
- 반대로 폭이 가장 넓은 638px는 **820px 이하 모바일/태블릿 1열 구간**이다. 즉 "폭이 넓을 때 2열"을 컨테이너 쿼리로 구현하면 정작 데스크톱에서는 발동하지 않고 모바일에서만 발동하는 역전이 생긴다.

**확정안**
- `prompt-stage`는 **항상 1열 세로 적층**한다. 탐색 → 장면 요약 → 미리보기 → 적용 순서는 유지한다.
- `grid-template-columns: minmax(0, 1fr)`로 선언해 두고, `@container (min-width: 900px)` 가드만 남긴다. 컴포저가 실제로 900px 이상이 되는 레이아웃 변경이 생기면 그때 2열이 켜지고, 현재 구성에서는 발동하지 않는다.
- `.workspace` 열 비율은 **바꾸지 않는다.** 바꾸면 작업 큐·갤러리와 함께 흔들린다.

이 결정으로 U01 §2의 데스크톱 2열 와이어프레임은 **폐기**한다. 대신 §3의 1열 흐름을 데스크톱에도 적용한다. 화면 폭을 넓히는 문제(예: 큐 접기, 전체 폭 모드)는 별도 검토 없이는 하지 않는다.


## 5. 상태별 표시 표

`P` = 미리보기 영역, `A` = 적용 영역, `S` = 상태 문구, `F` = 최종 입력.

| 상태 | 탐색(좌) | 장면 요약 | P 미리보기 | A 적용 버튼 | S 상태 문구 | 원문 포함 여부 표시 |
| --- | --- | --- | --- | --- | --- | --- |
| **빈 상태** (선택 0, 원문 0) | 전체 목록 + "대상부터 골라 보세요" | "선택한 항목이 없습니다" + 시작 안내 | 숨김 또는 "선택하거나 설명을 입력하면 미리보기가 만들어집니다" | 숨김 | `미적용` | 해당 없음 |
| **8개 선택** (원문 없음) | 필터 밖 선택 유지 안내 | 분류별 그룹 칩 8개 | 자동 생성된 최신 초안 | 활성(최종 입력과 다르면 덮어쓰기 확인) | `미적용` / `적용 후 수정됨` | `원문 없음` |
| **원문 포함(verbatim)** | 동일 | 칩 + 원문 요약 | 초안 + `원문 포함 · 번역 안 함` | 활성 | `미적용` | **포함**을 미리보기 기준으로 명시 |
| **별도 보관(separate)** | 동일 | 칩 + 원문 요약 | 사전 초안만, `별도 보관 · 미리보기 미포함` | 초안 있으면 활성 / 없으면 "설명만 이력에 적용" | `미적용` | **미포함** 명시 |
| **최종 직접 수정** (적용 후) | 동일 | 동일 | 최신 초안 유지 | 재적용 가능 | `적용 후 수정됨` | 미리보기 기준 안내 유지, 최종과 다를 수 있음 명시 |
| **과거 복원** (`provenance=saved`) | 동일 | 저장된 선택 칩 | 저장된 초안, 경고/출처 없음 | "현재 컴파일러로 다시 만들기" 후 적용 | `과거 복원 · 방식 기록 없음` | **방식 기록 없음**(추정 금지) |
| **계열 전환** (다른 계열) | 동일 | 재결속된 칩 | result 비움 → 재생성 필요 | 재생성 전 비활성 | `계열 변경 · 미리보기 없음` | 해당 없음(재생성 후 결정) |

이 표가 U02–U08의 계약이다. **U08만 `F`(최종 입력) 오류 시점을 다루고, 나머지는 `P`/`A`/`S`를 다룬다.**

## 6. 줄이는 스크롤 왕복 (실측 아님)

현재 구조에서 한 장면을 구성하면 사용자는 **세로로 내려갔다가(목록) 올라오고(칩 확인) 다시 내려간다(미리보기/적용)**. 2열이 되면 좌우로만 움직여 왕복이 줄어든다.

- 정성적 기대: "목록 → 칩 → 미리보기" 왕복이 좌우 시선 이동으로 바뀐다.
- **수치를 만들지 않는다.** 클릭 수/스크롤 거리 측정은 U11에서 실제 브라우저로 수행한다.
- §4 실측으로 2열이 불가능해졌으므로, 이 절의 기대는 **성립하지 않는다.** 현재 구현은 여전히 세로 왕복이 남는다. 왕복 자체를 줄이려면 (a) 목록과 칩을 같은 화면 높이에 두는 sticky 목록, (b) 적용 버튼을 컴포저 상단에 두는 안, (c) 큐를 접어 컴포저 폭을 넓히는 안 중 하나를 별도 검토해야 한다. U02에서는 어느 것도 하지 않았다.

## 7. U11 사용성 실측 (2026-11-16, Chromium 149 headless)

| 미리보기·적용 | 395 | 422 | +27 | 포함/보관 안내(U06) + 상태 문구(U07) |
| 마진·간격 상쇄 | — | — | −10 | `h3`의 `margin-bottom`과 인접 블록 마진이 겹쳐 합계보다 작다 |
| **컴포저 전체** | **1691** | **1766** | **+75** | 블록 증감 합 85 − 상쇄 10 |

즉 **늘어난 길이는 전부 "설명을 화면에 남긴 비용"**이다. 접었거나 숨긴 정보는 없다. `prompt-choices` 목록만 높이가 고정(230px)이라, 항목이 늘어나도 여기서는 늘지 않는다.

### 7.4 해석

- **개선된 것:** 클릭 1회 감소(자동 미리보기), §10 적용 후에는 검색창→적용 거리도 12–67px 감소, 마지막 칩→적용 86–122px 감소, 적용→최종 입력 10px 감소.
- **개선되지 않은 것:** U01 §6이 기대한 "왕복 감소"는 2열 폐기(§4)로 성립하지 않았다. §10은 **설명을 접어 길이를 되돌린 것**이지 왕복 구조를 바꾼 것은 아니다. 세로 순서(탐색→칩→미리보기→적용)는 그대로다.
- **역전 없음:** 양쪽 모두 검색→목록→칩→적용→최종 입력 순서가 단조 증가다(`docReversals=0`). 세로 왕복은 "읽는 순서"가 아니라 "같은 구간을 다시 지나가는 회수"에서 생기는데, 이 하네스는 그 회수를 측정하지 않는다. 실제 왕복은 사용자 스크롤 동작에 달려 있으므로 **추정하지 않는다.**
- **U11 완료 조건 중 사용자 의견 기록은 미완료다.** 이 수치를 사용자에게 제시하고 데스크톱/360/390px 의견을 받아야 한다. 무응답을 승인으로 처리하지 않는다.
- **U11 후속(§10):** 사용자가 "안내문구는 기본 접이"를 지시해 §10에서 구현했고, 위 표는 그 결과다. §9의 A/B/C는 채택하지 않았다.

### 7.5 실측이 잡아낸 회귀와 수정

U11 중 `선택 n`을 pill 두 번째 줄로 표시한 것이 390/360px에서 분류 칩을 102→146px로 늘린 것을 발견했다. 같은 줄에 이어 붙이고(`display: inline`), 460px 이하에서 pill 여백을 조여 **390px 106px / 360px 106px**로 되돌렸다. 1440px에서는 66→70px로 4px만 늘었다.

이 회귀는 U10의 38개 검사가 잡지 못했다. U10 검사는 "넘침 없음"·"적용 버튼 노출"만 봤고 **높이 증가는 판정 대상이 아니었기 때문**이다. U11이 높이를 재면서 드러났다.

## 8. U02 인계

- 확정 사항: ① form/onSubmit 유지 ② `.workspace` 열 비율 불변 ③ `PromptBuilder` 내부만 `prompt-stage`(탐색 | 장면·미리보기) 2구획 ④ 최종 입력·파라미터·생성 버튼 위치 불변 ⑤ sticky 없음 ⑥ 모바일 1열 고정.
- U02에서 할 일: `PromptBuilder.tsx`와 `styles.css`만 수정. App은 class/prop 수준 최소 변경. 기존 클래스(`.prompt-choices`, `.prompt-selected`, `.prompt-result` 등)는 유지하고 wrapper/구획 클래스만 추가한다.
- 구조 결정이 더 필요하면(예: 2열 기준 960px 조정) **U02에서 실측 후 보고**하고, 임의로 App 구조를 뜯지 않는다.

## 9. U11에서 제안하는 다음 선택지 (승인 필요)

§4로 2열이 불가능해졌고 §7에서 세로 거리가 오히려 늘어난 것이 확인됐다. 거리를 줄이려면 아래 중 하나가 필요하지만 **모두 U11 범위 밖이며 승인 없이 하지 않는다.**

| 안 | 내용 | 예상 효과 | 비용·위험 |
| --- | --- | --- | --- |
| A. 목록 sticky 축소 | 선택 영역에 들어가면 목록을 접거나 높이를 줄여 칩·미리보기를 위로 당김 | 검색→적용 거리 감소 | 목록 재검색 시 다시 펼쳐야 함 |
| B. 적용 버튼 상단 고정 | `prompt-result` 상단 또는 칩 바로 아래에 적용 버튼을 하나 더 둠 | 마지막 칩→적용 거리 감소 | 버튼 2개 = 클릭 대상 모호, 기존 계약과 충돌 검토 필요 |
| C. 컴포저 폭 확장 | 작업 큐를 접거나 컴포저 전체 폭 모드 제공 | 2열 가능(900px 이상) | `.workspace` 변경 = U02 금지 범위, 큐·갤러리 영향 |

측정상 **A가 가장 안전**하다(다른 화면 영향 없음). 다만 U11은 계측까지만 하고 구현은 하지 않았다.
