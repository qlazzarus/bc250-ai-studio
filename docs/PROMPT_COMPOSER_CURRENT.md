# 현재 프롬프트 구성

기존 직접 프롬프트 입력에 사전 기반 구성과 선택적 LLM 제안을 더하는 방식이다. **한글 전체를 한 번에 해석해 사전을 자동 선택하고 완성된 영어 후보를 만드는 기능은 아직 없다.** 해당 개선은 [최우선 TODO](PROMPT_COMPOSER_UNIFIED_IMPLEMENTATION.md)다.

## 입력과 적용 흐름

구성 패널에서 한글 설명을 입력하거나 사전 항목을 선택한다. 선택 변경으로 로컬 영어 초안을 갱신하고, 사용자가 최종 입력에 적용한 뒤 이미지 생성을 요청한다. 초안은 읽기 전용이고 최종 입력은 직접 편집할 수 있다.

사전 검색·분류, 선택 수, 그룹별 칩·삭제, 빈 검색 복구, 영어 표현 상세와 경고를 제공한다. 예시는 입력만 채운다. 사전 세부 조정은 접을 수 있다. 최종 입력을 직접 수정한 상태의 초안 교체는 확인을 거친다.

자유 입력은 기본적으로 별도 보관하며 자동 번역하지 않는다. 원문 반영 방식에서는 한국어를 그대로 초안에 붙인다. 이 두 방식과 사전 밖 구절의 LLM 번역 포함은 별개다. 입력 상태는 메모리에 있으며 새로고침 전 영속 초안 저장은 없다.

## 사전과 컴파일러

`frontend/src/prompt/dictionary.ts`는 버전 1.2.0의 활성 항목 100개를 정의한다. `scripts/gen-prompt-dictionary.mjs`가 서버용 `config/prompt_dictionary.json`을 생성한다. 안정 ID, 한글 이름/별칭, 분류, 계열별 표현을 사용한다.

컴파일러 1.3.0은 선택 스냅샷을 분류·ID 순서로 정렬하고 같은 영어 표현을 중복 제거한다. `sd15`는 쉼표, `z-image`/`flux2`/`moss-image`는 세미콜론으로 연결한다. 알 수 없는 계열과 매핑 없는 선택은 미변환으로 남긴다. 이는 문장 전체의 모델별 최적화가 아니다.

전역 충돌 쌍과 머리색 배타 그룹을 경고한다. 인물별 속성 귀속은 없으며 Scene은 평면 선택 구조다. SD 1.5 토큰 경고는 근사치이며 실제 엔진 tokenizer/잘림 검증이 아니다.

## 규칙 제안과 LLM 제안

| 기능 | 현재 동작 |
| --- | --- |
| 원문에서 사전 찾기 | 이름·별칭, 발생 단위 부정·복수·수·단어 경계를 검사하는 로컬 규칙 |
| 장면 정리 | `selection_hint`로 사전 ID 제안. 자동 적용하지 않음 |
| 부분 변경 | `partial_change`, 지정 그룹 외 선택은 잠금. 설정 잠금이지 인물 동일성 보장은 아님 |
| 상황 3개 | `situation_variants`, 장소·행동의 ID 변경 후보. 한국어 문장 전체의 영어 변환이 아님 |
| 사전 밖 번역 | `remainder_translation`, 규칙으로 추출한 구절만 영어 제안 |

LLM은 버튼 클릭 때만 호출한다. capability와 사전 버전이 맞을 때 노출하며, 미지원이면 규칙 제안과 직접 입력을 유지한다. 요청 취소·timeout·revision 검사를 통해 늦은 응답의 반영을 막는다. 제안 수신만으로 원문·선택·최종 입력이 바뀌지 않는다.

제안 항목은 유효 사전 ID·활성·중복·충돌·계열 매핑을 확인한 뒤 개별 수락한다. 원문 근거 `quote`만 일괄 수락 대상이며 추론 항목은 개별 확인한다. 상황 적용과 제안 수락에는 상태 지문에 기반한 한 단계 되돌리기가 있다.

잔여 구절은 전체 활성 사전의 어휘 범위를 원문에서 제외해 추출한다. 전체 문장 의미 분석이 아니며 선택하지 않은 사전 단어도 잔여 번역에서 제외될 수 있다. 번역은 사용자가 포함해야 최종 프롬프트 뒤에 개행으로 붙는다. 상황 카드의 미변환 구절은 사전 ID 적용으로 영어에 자동 포함되지 않는다.

## 상태와 저장

`scene`은 편집 상태, `result`는 초안, `applied`는 마지막 적용 이력이다. 선택·원문 수정과 최종 입력 수정은 서로 독립적이다. 적용 후 수동 편집 여부와 장면 변경 여부를 표시한다.

모델 계열 변경 시 선택을 현재 사전 표현으로 재결속하지만 최종 입력과 적용 이력·번역 출처는 유지한다. 다시 적용하기 전에는 이전 기록을 새 계열 구성으로 보내지 않는다. 같은 계열 모델 변경은 현재 구현에서 계열 재결속을 하지 않는다.

구성 v1은 원문·선택 스냅샷·초안·미변환을 저장하고 v2는 수락한 번역 `remainder`를 추가한다. 번역마다 원문·영어·proposal ID·provider 모델·수락 시각을 저장한다. 서버는 구조를 검증하고 설명용 스냅샷으로 보관하며 실제 실행 기준은 최상위 `prompt`다. 상세 크기와 API는 [API](API.md)를 따른다.

구 서버가 v1만 지원하면 번역 기록을 제외한 v1을 보내고 저장 누락을 안내한다. 최종 영어 문자열은 유지된다. 구성 미지원 서버에는 구성 필드를 보내지 않는다. retry·DB·asset metadata·sidecar로 기록이 전달되며 갤러리 재사용은 당시 스냅샷을 복원한다. 기록되지 않은 적용 방식이나 출처는 추정하지 않는다.

## 코드 위치

| 위치 | 책임 |
| --- | --- |
| `components/PromptBuilder.tsx` | 구성 UI와 이벤트 |
| `prompt/scene.ts`, `builderState.ts`, `compiler.ts` | 선택·상태·초안 |
| `prompt/llmProposals.ts`, `proposalCards.ts`, `partialChange.ts` | 요청 생명주기·제안·범위 |
| `prompt/situationVariants.ts`, `variantApply.ts` | 상황 카드와 적용 |
| `prompt/remainder.ts`, `remainderInclusion.ts` | 잔여 추출과 번역 포함 |
| `App.tsx`, `components/MetadataModal.tsx` | 제출·복원·이력 표시 |
| `backend/app/services/prompt_proposals.py`, `proposal_provider.py` | 서버 검증과 LLM 요청 |

프런트 경로는 `frontend/src/` 기준이다. 실제 LLM 의미 보존과 모델별 이미지 품질은 로컬 stub 검사와 구분하며 [검증 가이드](TESTING.md)를 따른다.
